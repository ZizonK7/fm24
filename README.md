# FM24 Player Tracker

Football Manager 2024에서 export한 선수 HTML을 **게임 내 날짜별로 누적 저장**하고,
다음 하나의 질문에 답하기 위한 로컬 도구다.

> **내가 데려온 선수들이 실제로 잘 성장하고 있고, 주전으로 쓸 만한가?**

그래서 화면과 지표가 전부 이 질문에 맞춰져 있다.

* **내가 데려온** — 이적료와 이전 구단으로 영입/유스를 자동 구분한다
* **실제로 성장** — 스냅샷 사이의 능력치 변화를 누적한다
* **주전으로 쓸 만한가** — 절대 점수가 아니라 **같은 포지션 경쟁자와 비교**한다

지표 계산식은 원본과 분리돼 있어서, 공식을 바꿔도 HTML을 다시 읽을 필요가 없다.

## 현재 이 저장소의 상태

첫 스냅샷이 이미 들어가 있다.

| | |
|---|---|
| 원본 | `data/raw/2027-03-07.html` (384컬럼, 42명) |
| game_date | **2027-03-07 — 추정치** |
| 결과 | 정규화 필드 86/86, 능력치 40/40, fallback ID 0 |

**game_date가 추정치인 이유:** export 당시의 정확한 세이브 날짜를 몰라서,
각 선수의 생년월일과 나이를 교차 검증해 가능한 범위를 좁혔다.
결과는 **2027-03-03 ~ 2027-03-11** 이었고 그 중앙값을 썼다.

절대 날짜보다 **스냅샷 사이 간격**이 중요하므로 9일 오차는 실질적 영향이 거의
없다. 다만 정확한 날짜를 알게 되면 다시 넣는 편이 낫다:

```powershell
Remove-Item db/fm24.db
python scripts/update.py --file data/raw/2027-03-07.html --date <정확한 날짜>
```

다음 export부터는 세이브 화면의 날짜를 그대로 `--date` 에 넣으면 된다.

## 1. 화면은 두 곳에서 열린다

| | 주소 | 할 수 있는 것 |
|---|---|---|
| **로컬** | <http://localhost:8765> | 불러오기 · 수정 · 동기화 **전부** |
| **클라우드** | <https://pfkfks.org/fm24> | **조회만** (관리자 로그인 필요) |

같은 화면 코드가 주소를 보고 모드를 고른다([`web/static/datasource.js`](web/static/datasource.js)).

**진실은 언제나 내 PC의 `db/fm24.db` 하나다.** 클라우드는 그걸 복사해 보여줄
뿐이라 읽기 전용이다. 양쪽에서 쓰게 만들면 SQLite와 Firestore를 양방향으로
맞춰야 하는데, 그건 이 도구의 목적에 비해 과하고 조용히 어긋나기 쉽다.

### 밖에서도 보려면 — 동기화

1. 로컬 앱에서 평소처럼 export를 불러온다
2. 우측 상단 **Firestore 동기화** 를 누른다 (처음엔 구글 로그인)
3. <https://pfkfks.org/fm24> 에서 확인

동기화는 **전량 덮어쓰기**다. 로컬에서 사라진 선수는 클라우드에서도 지워진다.

터미널에서 띄우고 싶으면:

```powershell
python scripts/serve.py            # 포트 8765
python scripts/serve.py --port 9000 --no-browser
```

> 주소가 `127.0.0.1` 이 아니라 `localhost` 인 이유: Firebase Auth의 기본 승인
> 도메인에 `localhost` 는 있지만 숫자 주소는 없어서, 숫자로 열면 동기화
> 로그인이 막힌다. 바인딩은 여전히 127.0.0.1이라 외부 노출은 없다.

### 화면 구성

**첫 화면 = 목적 그 자체.** 기본 필터는 **전체**(출신·나이 모두)이고,
기본 정렬이 **주전까지 남은 격차** 순이다. 즉 "주전에 가장 가까운 순서"로
선수단 전체가 바로 보이고, 필요하면 영입/유스·21세 이하 칩으로 좁히면 된다.

**상태 필터만 예외다.** 기본값이 「현재 스쿼드」라서, 임대 나간 선수와 떠난
선수는 처음에 보이지 않는다. 지금 내가 쓸 수 있는 자원이 아니기 때문이다.
「임대 포함」을 누르면 임대 나간 선수까지, 「전체」를 누르면 떠난 선수까지
나온다. 이 둘은 **추천 포메이션에서도 빠진다.**

| 상태 | 판정 근거 | 꼬리표 |
|---|---|---|
| 정상 | `구단` 이 모구단과 같다. **임대로 와 있는 선수도 여기 포함**한다 | 없음 |
| 임대 | `구단` 이 모구단과 다르다 (임대 나가면 임대처로 찍힌다) | `임대` |
| 방출 | 그 시점 명단에서 사라졌다 | `방출` |

모구단은 export에서 **과반을 차지하는 구단**으로 판정해 시점마다 기록해
둔다(`squad_meta`). 기록이 없는 옛 데이터는 저장된 스냅샷에서 역산하므로,
다시 import할 필요는 없다.

| 열 | 뜻 |
|---|---|
| 경쟁 | 그 자리를 소화하는 스쿼드 인원 중 몇 위인가 (`4/15`) |
| 실력 | **그 포지션의 핵심 능력치**만 평균 (1~20) |
| 주전까지 | 그 자리 1위와의 능력치 차이. 막대가 오른쪽(초록)이면 이미 최고 |
| 성장 | 직전 스냅샷 대비 능력치 총 변화 |
| 출전 | 스쿼드 내 최대 출장시간 대비 비율 |

선수를 **클릭**하면 오른쪽에 상세가 열린다 — 시점별 추이, 능력치 변화 내역,
포지션 핵심 능력치(강조 표시), 그리고 한 줄 판단:

> 2027-03-07 → 2027-08-15 사이에 능력치가 **+5** 올랐습니다.
> 주전과의 격차가 **1.8만큼 좁혀졌습니다**. 역할은 육성 → 로테이션 입니다.

상세의 **실력 그래프**는 게임 내 날짜를 가로축으로 두고 실력 점수를 직선으로
이어 보여준다. 점에 마우스를 올리면 해당 날짜의 점수와 직전 기록 대비 변화를
확인할 수 있다.

### 데이터 불러오기

우측 상단 **데이터 불러오기** 버튼 → 파일을 끌어다 놓거나 선택
(또는 `data/` 에 이미 있는 파일에서 고르기).

* **파일명이 `270424.html` 이면 날짜가 2027-04-24로 자동 입력된다.**
  `2027-04-24.html`, `270424`, `20270424` 전부 인식한다.
* 가져오기 전에 **몇 명 / 몇 컬럼 / 능력치 몇 개 인식** 을 보여주므로,
  엉뚱한 파일을 넣었는지 바로 알 수 있다.
* 날짜는 항상 고칠 수 있다. 파일명 추론은 어디까지나 기본값이다.

### 자동 판정을 고치기

상세 패널 아래에서 **역할**(주전/로테이션/육성/잉여)과
**출신**(영입/유스)을 직접 바꿀 수 있다.
직접 지정한 값은 **이후 import가 덮어쓰지 않는다.**

이름을 정확히 입력할 일은 없다. 전부 목록에서 고르면 된다.

### 포지션 설정과 추천 스쿼드

선수 상세의 **포지션 설정**에서 주 포지션 하나와 다른 가능 포지션을 직접 고를 수 있다.
저장한 포지션은 다음 HTML import에도 유지되며, 주 포지션을 기준으로 실력과
포지션 경쟁 지표를 다시 계산한다. 설정 전에는 FM export의 포지션을 사용한다.

상단 **추천 포메이션** 탭은 선택한 시점의 전체 선수단으로 **4-2-3-1**,
**4-3-3 DM**, **4-4-2**, **3-4-2-1** 중 하나를 골라 주전·로테이션·육성
3개 스쿼드를 보여준다. 포지션별 핵심 능력치, 운영 역할,
육성 스쿼드의 나이를 반영한다. 같은 선수는 한 스쿼드에만 배치하고,
소화 가능한 선수가 부족한 자리는 비워 둔다. 추천은 저장된 명단이 아니라
현재 데이터로 매번 계산된다.

## 2. CLI로 쓰기

사이트 없이 터미널만 써도 된다. 기능은 같다.

### 1) FM24에서 export

선수 목록 화면 → 우클릭 → **Print Screen / 웹 페이지로 내보내기** → HTML 저장.

export 열 설정에 **`ID` 컬럼을 반드시 포함**한다. 이름은 primary key로 쓰지 않는다
(동명이인, 뉴젠 이름 변경 때문). ID가 없으면 이름+생일+국적 해시를 임시로 쓰고
경고를 출력하는데, 그건 임시방편일 뿐이다.

```powershell
python scripts/update.py --file data/raw/270424.html --date 2027-04-24
```

생략하면 실행 중에 물어보고, 파일명이 `270424` 같은 형태면 그 값을
기본값으로 제시한다(Enter만 치면 사용).

같은 세이브에서 몇 달마다 export해서 같은 명령을 돌린다.

### 6) 역할 라벨 (starter / rotation / development / fringe)

**대부분 손댈 필요가 없다.** FM이 `실제 출전 시간` 컬럼에 이미 판정해두고
있어서 import할 때 자동으로 붙는다:

| FM 표기 | 역할 |
|---|---|
| 주전 선수, 중요 선수 | `starter` |
| 비주전 선수, 뛰어난 후보, 선수단 선수, 후보 | `rotation` |
| 어린 선수, 미래의 유망주, 눈부신 유망주 | `development` |
| 비상 후보, 잉여 자원 | `fringe` |

매핑은 `config.PLAYING_TIME_ROLE_MAP` 에서 고칠 수 있다.

자동 판정이 마음에 안 들면 사이트 상세 패널에서 직접 고르거나, CSV로:

```csv
player_id,game_date,role,note
29221846,2027-03-07,starter,
29221847,2027-03-07,development,겨울에 1군 합류 예정
```

```powershell
python scripts/update.py --file data/raw/270424.html --date 2027-04-24 --roles roles.csv
```

**사람이 넣은 라벨은 이후 import가 덮어쓰지 않는다.**
라벨은 지정한 날짜부터 다음 라벨이 나올 때까지 유효하다.

## 1-2. pfkfks.org/fm24 에 화면을 배포하기

`web/static/`을 수정해 이 저장소의 `main`에 push하면 GitHub Actions가
화면 파일을 `pfkfks-main/public/fm24/`에 복사해 커밋한다. 이어서
`pfkfks-main`의 기존 Firebase Hosting 배포가 자동으로 실행된다.
HTML 데이터는 별도로 로컬 앱에서 **Firestore 동기화**를 눌러야 한다.

수동으로 화면을 복사해야 할 때는 `python scripts/deploy_web.py`를 사용할 수 있다.

**왜 복사하는가:** Firebase Hosting 배포는 **사이트 전체를 교체한다.**
이 저장소에서 직접 배포하면 pfkfks.org의 나머지(/work, /study, /football…)가
전부 날아간다. 그래서 화면 파일은 `pfkfks-main/public/fm24/` 안에 있어야 하고,
이 저장소는 원본만 갖는다.

배포에 함께 필요한 것 (한 번만 해두면 된다):

| 무엇 | 어디 | 비고 |
|---|---|---|
| `/fm24` 라우팅 | `pfkfks-main/firebase.json` | rewrites, catch-all `**` 보다 **앞**에 |
| Firestore 규칙 | `pfkfks-main/firestore.rules` | `match /fm24/{document=**}` → `isAdmin()` |
| 접근 UID | `web/static/firebase-config.js` 의 `ALLOWED_UIDS` | 규칙의 `isAdmin()` 과 **맞춰야 함** |

Firestore 규칙은 GitHub Actions가 배포하지 않는다(hosting만 한다). 규칙을
고쳤으면 수동으로:

```powershell
cd ../pfkfks-main
firebase deploy --only firestore:rules --project pfkfks
```

### Firestore 구조

```
fm24/overview                   전체 요약 1건
fm24/index/snapshots/{날짜}      그 시점 스쿼드 전체
fm24/index/players/{선수id}      선수별 상세 이력
```

원본 384컬럼(`raw_json`)은 **올리지 않는다.** 화면에 쓰는 것만 비정규화해
담는다 — Firestore는 조인을 못 하고, 문서 한도(1MB)도 아껴야 한다.
현재 선수 문서 최대 6.3KB, 스냅샷 문서 28KB.

## 2. 계산식을 바꾸고 싶을 때

**HTML을 다시 import할 필요가 없다.**

1. `src/metrics.py` 의 함수를 고친다 (또는 `@metric` 으로 새 지표를 등록한다).
2. `FORMULA_VERSION` 을 올린다.
3. 재계산:

```powershell
python scripts/recompute.py
```

`snapshots` / `snapshot_attributes` 는 그대로 두고
`growth_deltas` / `derived_metrics` 만 다시 만든다.

능력치 그룹(`src/config.py` 의 `ATTRIBUTE_GROUPS`)을 고쳤을 때도 같다.
다만 **새로 추가한 능력치는 과거 스냅샷에 저장돼 있지 않으므로**,
그 능력치까지 소급하려면 과거 HTML을 다시 import해야 한다
(원본 파일을 `data/raw/` 에 보관해두는 이유다).

## 4. 데이터베이스 스키마

### `players` — 선수 1명당 1행

| 컬럼 | 설명 |
|---|---|
| `player_id` | FM export의 ID (primary key) |
| `name`, `birth_date`, `nationality`, `primary_position` | 가장 최근 관측값 |
| `first_seen_date`, `last_seen_date` | 관측 범위 (게임 내 날짜) |
| `id_source` | `export` 또는 `fallback` |

### `snapshots` — `(player_id, game_date)` 당 1행

정규화된 주요 필드(약 90개 컬럼)와 **`raw_json` 에 export 원본 384컬럼 전부**.

컬럼 구성은 `config.FIELD_SPECS` 에서 자동 생성된다. config에 필드를 추가하고
`update.py` 를 돌리면 `ALTER TABLE ADD COLUMN` 이 알아서 실행된다.

정규화하지 않은 FM 필드는 이렇게 꺼낸다:

```python
from src import database
snapshot = database.get_snapshot(conn, "29221846", "2027-03-01")
database.raw_value(snapshot, "훈련 만족도")
```

### `snapshot_attributes` — 능력치 (long 형태)

```
player_id | game_date | attribute | attr_group | value
```

넓은 컬럼 대신 긴 형태를 쓰는 이유: 능력치를 추가해도 스키마를 안 바꿔도 되고,
성장 계산이 self-join 하나로 끝난다.

### `growth_deltas` — 능력치 변화 (파생)

```
player_id | game_date | prev_game_date | attribute | previous | current | delta
```

### `derived_metrics` — 파생 지표 (key-value)

```
player_id | game_date | metric | value_num | value_text | formula_version
```

고정 컬럼(quality/ceiling/growth/usage) 대신 key-value로 둔 이유:
지표를 새로 추가할 때 마이그레이션이 필요 없다.
`formula_version` 이 함께 저장되므로 어떤 공식으로 계산한 값인지 추적된다.

### `squad_roles` — 운영 역할 라벨

```
player_id | game_date | role | source | note
```

`source` 가 `fm_auto` 면 FM의 `실제 출전 시간` 에서 자동으로 붙인 것,
`manual`/`csv`/`cli` 면 사람이 넣은 것이다.
**자동 판정은 사람이 넣은 값을 덮어쓰지 않는다.**

### `player_origin` — 영입/유스 구분

```
player_id | origin | signed_from | signed_fee | joined_date | manual_origin
```

`manual_origin = 1` 이면 사람이 직접 지정한 것이라 자동 판정이 덮어쓰지 않는다.

### `squad_meta` — 시점별 모구단

```
game_date | parent_club | updated_at
```

임대 나간 선수는 `구단` 이 임대처로 찍히므로, "우리 팀" 이 어디였는지
시점마다 기억해야 임대 여부를 판별할 수 있다. import가 과반 구단으로
판정해 넣는다. 값이 없으면 조회 시 스냅샷에서 역산해 채운다.

### 목적에 직접 답하는 것

| 지표 | 정의 | 읽는 법 |
|---|---|---|

| 축 | v0.1 정의 | 한계 |
|---|---|---|
| **Quality** | **포지션별** 핵심 능력치의 평균 (1~20) | 목록 안에서는 아직 가중치가 없다 (동등 평균) |

### 1. 스트라이커 — 완성형 포워드(공격) / 전진형 포워드(공격)

스트라이커는 하나의 공통 지수로 묶지 않는다. 현재 사용하는 역할은 두 가지다.

- **완성형 포워드(공격)**: 공격의 중심이 되며, 등을 지고 버티고 연결하면서 직접 득점까지 하는 다기능형 9번
- **전진형 포워드(공격)**: 빠른 속도와 뒷공간 침투를 이용해 수비 라인을 깨고 직접 득점하는 공격수

두 역할 모두 득점력은 중요하지만, 완성형 포워드는 **버티기와 연결 능력**,
전진형 포워드는 **침투와 폭발력**을 추가 핵심으로 본다.

#### 완성형 포워드(공격)

이상적인 유형은 해리 케인처럼 **키와 피지컬이 있고, 등을 지고 공을 지켜내며,
패스로 공격을 연결하고, 박스 안에서는 직접 득점까지 할 수 있는 완성형 9번**이다.

현재는 Jayden Danns를 이 역할로 사용하고 있다.

최종 적합도 가안은 다음과 같다.

```text
ST_CF_A =
0.30 * Finishing
+ 0.25 * HoldUp
+ 0.20 * LinkPlay
+ 0.15 * Movement
+ 0.10 * Aerial
```

| 하위 지수 | 비중 | 의미 |
| --- | --- | --- |
| **Finishing** | 30% | 박스 안에서 기회를 득점으로 끝내는 능력 |
| **HoldUp** | 25% | 등을 지고 공을 보호하며 공격을 이어가는 능력 |
| **LinkPlay** | 20% | 주변 공격수와 연결하고 찬스를 이어주는 능력 |
| **Movement** | 15% | 박스 안팎에서 좋은 위치를 선점하는 움직임 |
| **Aerial** | 10% | 공중볼과 제공권을 이용해 공격에 기여하는 능력 |

##### Finishing — 득점력

```text
0.35 * 골결
+ 0.25 * 침착
+ 0.15 * 오프더볼
+ 0.15 * 예측
+ 0.10 * 기술
```

이 역할에서 가장 중요한 축이다. 단순히 슈팅 능력만 보는 것이 아니라,
좋은 위치를 잡고 압박 속에서도 침착하게 마무리할 수 있어야 한다.

특히 **골결정력과 침착성**을 핵심 능력으로 본다.

##### HoldUp — 등지고 버티기

```text
0.25 * 몸싸움
+ 0.20 * 균형
+ 0.20 * 트랩
+ 0.15 * 침착
+ 0.10 * 기술
+ 0.10 * 판단
```

완성형 포워드는 공을 받자마자 잃지 않고, 센터백을 등진 상태에서 공을 지켜내며
주변 선수들이 올라올 시간을 만들어야 한다.

몸싸움과 균형뿐 아니라 첫 터치와 침착성도 중요하게 본다.

##### LinkPlay — 연계

```text
0.25 * 패스
+ 0.20 * 시야
+ 0.15 * 판단
+ 0.15 * 팀워크
+ 0.15 * 트랩
+ 0.10 * 기술
```

공격의 종착점만이 아니라 공격 전개 과정에도 참여할 수 있어야 한다.
공미나 윙에게 다시 공을 내주거나, 침투하는 선수를 보고 연결할 수 있는 능력을 평가한다.

##### Movement — 움직임

```text
0.35 * 오프더볼
+ 0.20 * 예측
+ 0.20 * 판단
+ 0.15 * 침착
+ 0.10 * 순간속도
```

박스 안에서 좋은 위치를 잡는 능력과 연계 후 다시 득점 위치로 들어가는 움직임을 본다.

##### Aerial — 제공권

```text
0.35 * 헤더
+ 0.30 * 점프
+ 0.20 * 몸싸움
+ 0.15 * 예측
```

완성형 포워드에게는 일정 수준의 제공권을 요구한다.
키 자체도 중요하게 보며, 이 초안에서는 **185cm 미만이면 감점**한다.

다만 키가 조금 작더라도 점프력, 몸싸움, 헤더 능력이 충분히 높다면 일부 상쇄할 수 있게 한다.
구체적인 감점과 상쇄는 아래 공통 규칙의 신장 보정을 적용한다.

이 역할의 핵심은 **버티고, 연결하고, 움직이고, 결국 골까지 넣는 공격의 중심**이다.

#### 전진형 포워드(공격)

이상적인 유형은 음바페처럼 **빠른 속도로 수비 뒷공간을 파괴하고,
좋은 침투 타이밍과 마무리 능력으로 직접 득점하는 공격수**다.

현재는 이삭, 호드리구, 바르콜라를 이 역할로 사용하고 있다.

최종 적합도 가안은 다음과 같다.

```text
ST_AF_A =
0.35 * Run
+ 0.30 * Finishing
+ 0.20 * Explosiveness
+ 0.15 * Carry
```

| 하위 지수 | 비중 | 의미 |
| --- | --- | --- |
| **Run** | 35% | 수비 라인 뒤의 공간을 읽고 침투하는 능력 |
| **Finishing** | 30% | 침투 이후 기회를 실제 득점으로 끝내는 능력 |
| **Explosiveness** | 20% | 짧은 순간에 수비수와 거리를 벌리는 폭발력 |
| **Carry** | 15% | 공간이 있을 때 공을 직접 운반하며 수비를 무너뜨리는 능력 |

##### Run — 뒷공간 침투

```text
0.30 * 오프더볼
+ 0.20 * 예측
+ 0.15 * 판단
+ 0.15 * 주력
+ 0.10 * 순간속도
+ 0.10 * 침착
```

전진형 포워드의 가장 중요한 능력이다. 단순히 빠른 선수가 아니라,
**수비 라인의 위치를 읽고 정확한 순간에 뒷공간으로 출발하는 선수**를 높게 평가한다.

따라서 오프더볼과 예측이 속도만큼 중요하다.

##### Finishing — 득점력

```text
0.35 * 골결
+ 0.25 * 침착
+ 0.15 * 오프더볼
+ 0.15 * 예측
+ 0.10 * 기술
```

침투 자체보다 중요한 것은 그 장면을 골로 끝내는 것이다.
특히 이 역할에서는 **골결정력과 침착성**을 주력과 가속도만큼 중요한 핵심 능력으로 본다.

##### Explosiveness — 폭발력

```text
0.40 * 순간속도
+ 0.35 * 주력
+ 0.15 * 민첩
+ 0.10 * 균형
```

첫 몇 걸음에서 수비수를 떼어내고, 열린 공간에서는 그대로 도망갈 수 있는 능력을 본다.
전진형 포워드에서는 주력과 순간속도 모두 높은 선수를 특히 선호한다.

##### Carry — 전진 드리블

```text
0.30 * 드리블
+ 0.20 * 순간속도
+ 0.15 * 주력
+ 0.15 * 기술
+ 0.10 * 트랩
+ 0.10 * 균형
```

항상 패스를 받아 바로 슈팅할 수 있는 것은 아니기 때문에,
공간이 열렸을 때 직접 공을 몰고 전진할 능력도 필요하다.

다만 이 역할의 정체성은 **침투형 득점자**이므로 비중은 상대적으로 낮게 둔다.

#### 두 역할의 핵심 차이

| 역할 | 핵심 철학 |
| --- | --- |
| **완성형 포워드(공격)** | 버티기 + 연계 + 다재다능함 + 득점 |
| **전진형 포워드(공격)** | 침투 + 폭발력 + 뒷공간 파괴 + 득점 |

완성형 포워드는 공격의 중심으로서 공을 받아 공격을 이어갈 수 있어야 하고,
전진형 포워드는 다른 선수들이 만든 공간과 패스를 이용해 수비 라인을 직접 무너뜨리는 역할이다.

두 역할 모두 공통적으로 **골결정력과 침착성은 최상위 핵심 능력**으로 본다.

### 2. 좌윙 — 인사이드 포워드(공격)

윙어도 공을 잃으면 즉시 다시 뛰고, 필요하면 풀백 위치까지 내려와 수비하는 책임감을\
요구한다. 좌윙은 전통적인 터치라인 윙어보다 **왼쪽에서 출발하는 득점형 공격수**에\
가깝게 본다. 선호 이미지는 비니시우스처럼 뒷공간을 파고들고, 호날두처럼 박스 안으로\
들어가 골을 노리는 인사이드 포워드(공격)다.

최종 좌윙 적합도는 네 축을 1~20 스케일로 계산한다.

```text
LW_IFA = 0.30 * Run + 0.30 * Goal + 0.20 * Carry + 0.20 * DefWork
```

| 하위 지수 | 비중 | 의미 |
| --- | --- | --- |
| **Run** | 30% | 타이밍을 읽고 뒷공간을 파괴하는 침투력 |
| **Goal** | 30% | 박스 안으로 들어가 공격을 득점으로 끝내는 능력 |
| **Carry** | 20% | 왼쪽에서 공을 받아 직접 전진하고 수비를 깨는 능력 |
| **DefWork** | 20% | 공을 잃은 뒤 재압박하고 수비 위치까지 복귀하는 책임감 |

#### Run — 침투력

```text
0.25 * 오프더볼
+ 0.20 * 순간속도
+ 0.15 * 주력
+ 0.15 * 예측
+ 0.15 * 판단
+ 0.10 * 민첩
```

단순히 빠른 선수보다 **언제 뛰어야 하는지 알고 먼저 움직이는 선수**를 높게 본다.\
그래서 오프더볼이 가장 큰 비중을 가진다.

#### Goal — 득점력

```text
0.30 * 결정
+ 0.20 * 침착
+ 0.20 * 오프더볼
+ 0.15 * 예측
+ 0.10 * 트랩
+ 0.05 * 헤더
```

결정력만 보는 것이 아니라 좋은 위치를 먼저 잡고, 박스 안에서 침착하게 마무리하는\
능력을 함께 본다. 오프더볼은 침투와 득점 양쪽에서 중요한 능력이라 중복 반영한다.

#### Carry — 돌파/전진력

```text
0.20 * 드리블
+ 0.20 * 천재
+ 0.15 * 순간속도
+ 0.10 * 주력
+ 0.10 * 민첩
+ 0.10 * 기술
+ 0.10 * 트랩
+ 0.05 * 균형
```

이 역할의 좌윙은 크로스를 올리기보다 직접 안쪽으로 전진해 수비를 깨는 것이 우선이다.\
따라서 v0.1의 W 핵심 능력에 들어 있던 크로스는 이 지수에서는 제외한다.

천재성은 예상 밖의 움직임으로 수비를 벗겨내는 능력을 평가하기 위해 반영한다.
좌윙에서는 침투와 득점이 중심이므로, 천재성의 최종 점수 비중은 **4%**로 둔다.

#### DefWork — 수비 책임감

```text
0.30 * 활동량
+ 0.20 * 팀워크
+ 0.15 * 지구력
+ 0.15 * 승부욕
+ 0.10 * 적극성
+ 0.10 * 판단
```

윙어에게 풀백 수준의 태클·마킹 기술을 요구하는 것이 아니라, **공격이 끝났다고 자기**\
**일이 끝난 것으로 생각하지 않는 선수**를 높게 본다. 많이 뛰고, 동료와 함께 움직이며,\
공을 잃은 뒤 다시 수비에 참여할 수 있는지를 본다.

#### 수비 하한 패널티

전술 철학상 수비 참여는 선택 사항이 아니므로 가중평균만으로 끝내지 않는다.\
`DefWork < 12` 이면 다음 패널티를 적용한다.

```text
LW_IFA_final = clamp(LW_IFA - 0.5 * max(0, 12 - DefWork), 1, 20)
```

예를 들어 Run/Goal/Carry가 모두 19이고 DefWork가 8이면 단순 평균은 16.8이지만,\
패널티 적용 후 14.8이 된다. 공격력이 압도적이어도 팀의 기본 활동량 기준을 크게\
밑도는 선수는 높은 평가를 받지 못하게 하려는 장치다.

다른 역할도 아래 공통 규칙에 따라 기본 점수에 하한·감점 기준을 적용한다.

### 3. 공격형 미드필더 — 공격형 미드필더(공격)

공격형 미드필더는 우윙처럼 공격 전체를 조율하는 역할보다,\
**포켓 공간에서 공을 받아 직접 공격을 만들어내는 창조자**에 가깝게 본다.

중앙의 좁은 공간에서 공을 지켜내고, 압박을 벗기거나 수비 사이를 뚫은 뒤,\
마지막 패스를 찌르거나 직접 슈팅으로 공격을 끝낼 수 있어야 한다.

현재 이 역할의 기준점으로 보는 선수는 올리세이며,\
로테이션은 은구모하, 육성 자원은 마테우스 페르난데스다.

최종 공격형 미드필더 적합도는 다섯 축을 1~20 스케일로 계산한다.

```text
AM_A =
0.30 * PocketCreation
+ 0.25 * FinishingThreat
+ 0.20 * BallSecurity
+ 0.15 * SpaceAttack
+ 0.10 * DefWork
```

| 하위 지수 | 비중 | 의미 |
| --- | --- | --- |
| **PocketCreation** | 30% | 포켓에서 공을 받아 마지막 패스와 창조적인 선택을 만드는 능력 |
| **FinishingThreat** | 25% | 박스 주변과 포켓에서 직접 공격을 득점으로 끝내는 능력 |
| **BallSecurity** | 20% | 중앙의 압박 속에서도 공을 지키고 플레이를 이어가는 능력 |
| **SpaceAttack** | 15% | 수비 사이를 파고들거나 한 명을 벗기며 전진하는 능력 |
| **DefWork** | 10% | 공을 잃은 뒤 재압박하고 중앙 수비에 참여하는 책임감 |

#### PocketCreation — 포켓 창조성

```text
0.30 * 천재
+ 0.20 * 시야
+ 0.15 * 패스
+ 0.10 * 침착
+ 0.10 * 기술
+ 0.05 * 트랩
+ 0.05 * 판단
+ 0.05 * 예측
```

이 역할의 가장 중요한 능력이다.

단순히 패스를 많이 돌리는 조율자가 아니라,\
**수비수와 미드필더 사이의 좁은 공간에서 공을 받은 뒤**\
**결정적인 다음 장면을 만들어내는 선수**를 높게 평가한다.

포켓에서는 생각할 시간이 짧기 때문에\
시야와 패스뿐 아니라 침착성과 기술도 중요하게 본다.

특히 **천재성은 이 역할의 핵심 능력**으로 본다. 수비가 예상하지 못한 선택으로
좁은 공간에서 새로운 공격 기회를 만드는 선수를 높게 평가하도록,
포켓 창조성 안에서는 천재성에 가장 큰 비중을 둔다.

#### FinishingThreat — 득점 위협

```text
0.30 * 결정
+ 0.20 * 침착
+ 0.20 * 중거리
+ 0.10 * 오프더볼
+ 0.10 * 예측
+ 0.10 * 기술
```

공격형 미드필더는 도움만 만드는 역할이 아니다.

포켓에서 직접 박스로 침투하거나,\
박스 앞에서 공간이 생겼을 때 슈팅으로 공격을 끝낼 수 있어야 한다.

특히 이 역할에서는 결정력뿐 아니라 **중거리 슈팅 능력을 중요한 무기**로 본다.\
상대 수비가 내려앉았을 때 포켓이나 박스 외곽에서 직접 득점 위협을 줄 수 있어야 한다.

#### BallSecurity — 공 보존 / 압박 대응

```text
0.25 * 트랩
+ 0.20 * 기술
+ 0.15 * 드리블
+ 0.15 * 침착
+ 0.10 * 균형
+ 0.10 * 민첩
+ 0.05 * 몸싸움
```

공격형 미드필더가 활동하는 포켓 공간은 압박이 매우 강한 지역이다.

좋은 위치에서 공을 받아도 첫 터치가 불안하거나\
압박을 받자마자 공을 잃으면 역할이 성립하지 않는다.

따라서 이 축은 단순한 드리블 능력보다,\
**좁은 공간에서 공을 받고 지키며 다음 플레이까지 연결할 수 있는가**를 본다.

#### SpaceAttack — 포켓 돌파 / 공간 공략

```text
0.20 * 천재
+ 0.20 * 드리블
+ 0.15 * 오프더볼
+ 0.10 * 순간속도
+ 0.10 * 민첩
+ 0.10 * 예측
+ 0.10 * 판단
+ 0.05 * 주력
```

여기서의 공간 공략은 좌윙처럼 넓은 뒷공간을 장거리로 질주하는 움직임과 다르다.

센터백과 미드필더 사이로 파고들고,\
짧은 거리에서 한 명을 벗겨내며,\
포켓에서 박스 안으로 진입하는 능력을 중요하게 본다.

따라서 최고 속도보다는 천재성, 드리블과 오프더볼에 비중을 두고,
순간속도와 민첩성으로 짧은 공간에서의 실행 능력을 함께 본다.

천재성은 포켓에서 예상 밖의 패스를 만드는 것뿐 아니라 수비 한 명을 벗겨내는
창의적인 돌파에도 반영한다. 두 축을 합친 최종 점수에서 천재성의 비중은
**12%**다 (`30% × 30% + 15% × 20%`). 양쪽 윙의 **4%**보다 크게 반영한다.
이 비중은 전술적 선호를 표현한 가안이며, 경기 엔진의 효과를 검증한 수치는 아니다.

#### DefWork — 수비 책임감

```text
0.30 * 활동량
+ 0.20 * 팀워크
+ 0.15 * 지구력
+ 0.15 * 승부욕
+ 0.10 * 적극성
+ 0.10 * 판단
```

팀 전체 철학상 공격형 미드필더 역시 수비에서 완전히 자유롭지 않다.

다만 좌우 윙처럼 긴 거리를 복귀하는 역할은 아니기 때문에,\
전체 실력 지수에서 수비 책임감의 비중은 10%로 낮게 둔다.

공을 잃은 직후 중앙에서 재압박하고,\
상대의 전진 패스 경로를 방해하는 정도의 활동량은 요구한다.

#### 역할의 핵심 능력

이 역할에서 특히 중요하게 보는 능력치는 다음 여섯 가지다.

```text
천재성
침착성
패스
시야
골결
중거리
```

천재성은 **예측하기 어려운 창의적인 선택**을 대표하며, 이 역할의 정체성을 결정하는
핵심으로 본다. 침착성·패스·시야는 압박 속에서 기회를 발견하고 마지막 패스를
실행하는 능력을, 골결·중거리는 박스 안팎의 마무리를 담당한다.

여기에 트랩, 기술, 드리블이 받쳐줘야\
포켓에서 실제로 이 능력들을 사용할 수 있다.

이 역할의 핵심은 정적인 10번이나 경기 전체를 조율하는 플레이메이커가 아니라,

**좁은 포켓에서 공을 받아 압박을 버티고,**\
**한 명을 벗겨낸 뒤 패스나 슈팅으로 직접 공격을 완성하는 창조형 득점 미드필더**다.

### 4. 우윙 — 인버티드 윙어(지원)

우윙은 좌윙과 역할 철학이 다르다. 좌윙이 **왼쪽에서 출발하는 득점형 공격수**라면,\
우윙은 **오른쪽에서 출발하는 전방 플레이메이커**에 가깝게 본다.

역할은 인버티드 윙어(지원)이지만 단순히 안쪽으로 접고 패스하는 선수가 아니라,\
전방에서 공격을 조율하고 킬패스를 찌르며, 상황에 따라 크로스를 올리고 직접 득점까지\
할 수 있는 다기능 창조형 윙어를 목표로 한다.

현재 이 역할의 기준점으로 보는 선수 유형은 라민 야말과 모리슨이다.

최종 우윙 적합도는 다섯 축을 1~20 스케일로 계산한다.

```text
RW_IWS =
0.30 * Playmaking
+ 0.20 * Carry
+ 0.20 * ChanceCreation
+ 0.15 * GoalThreat
+ 0.15 * DefWork
```

| 하위 지수 | 비중 | 의미 |
| --- | --- | --- |
| **Playmaking** | 30% | 전방에서 공격 방향을 읽고 패스로 조율하는 능력 |
| **Carry** | 20% | 측면과 하프스페이스에서 공을 지키고 전진하는 능력 |
| **ChanceCreation** | 20% | 킬패스와 크로스로 직접 찬스를 만드는 능력 |
| **GoalThreat** | 15% | 직접 박스로 들어가 공격을 마무리하는 능력 |
| **DefWork** | 15% | 공을 잃은 뒤 재압박하고 수비에 복귀하는 책임감 |

#### Playmaking — 플레이메이킹

```text
0.25 * 시야
+ 0.20 * 패스
+ 0.15 * 판단
+ 0.15 * 기술
+ 0.10 * 트랩
+ 0.10 * 예측
+ 0.05 * 침착
```

이 역할의 가장 중요한 능력이다. 단순히 패스 성공률이 높은 선수가 아니라,\
**수비 움직임을 읽고 다음 장면을 만들어내는 선수**를 높게 평가한다.

특히 시야, 패스, 판단을 핵심 축으로 본다.

#### Carry — 볼 운반/압박 탈출

```text
0.25 * 드리블
+ 0.20 * 기술
+ 0.15 * 트랩
+ 0.15 * 민첩
+ 0.10 * 균형
+ 0.10 * 순간속도
+ 0.05 * 침착
```

좌윙처럼 뒷공간을 스프린트로 파괴하는 것보다,\
좁은 공간에서 공을 지키고 압박을 벗어나며 안쪽으로 전진하는 능력을 더 중요하게 본다.

따라서 주력보다는 드리블, 기술, 첫 터치, 민첩성의 비중이 높다.

#### ChanceCreation — 찬스 생산

```text
0.20 * 천재
+ 0.20 * 크로스
+ 0.15 * 패스
+ 0.15 * 시야
+ 0.10 * 기술
+ 0.10 * 판단
+ 0.05 * 오프더볼
+ 0.05 * 트랩
```

우윙은 공격 루트가 하나로 고정되지 않는다.

안쪽으로 들어와 킬패스를 찌를 수도 있고,\
바깥쪽에서 크로스를 올릴 수도 있으며,\
전방에서 공을 돌리면서 다른 공격수의 움직임을 살릴 수도 있어야 한다.

따라서 좌윙과 달리 크로스를 중요한 능력으로 포함한다.

천재성은 정형화된 패스와 크로스를 넘어 예상 밖의 찬스를 만드는 요소로 반영한다.
우윙 역시 기본적인 조율과 실행 능력을 중심에 두고, 천재성의 최종 점수 비중은
좌윙과 같은 **4%**로 둔다.

#### GoalThreat — 득점 위협

```text
0.25 * 결정
+ 0.20 * 침착
+ 0.15 * 오프더볼
+ 0.15 * 예측
+ 0.10 * 기술
+ 0.10 * 트랩
+ 0.05 * 롱슛
```

득점은 좌윙만큼 중심적인 역할은 아니지만,\
패스만 하는 플레이메이커가 아니라 직접 골까지 위협할 수 있어야 한다.

즉 우윙의 득점력은 역할의 핵심보다는\
**창조성을 완성하는 두 번째 공격 수단**으로 본다.

#### DefWork — 수비 책임감

```text
0.30 * 활동량
+ 0.20 * 팀워크
+ 0.15 * 지구력
+ 0.15 * 승부욕
+ 0.10 * 적극성
+ 0.10 * 판단
```

팀 전체 철학상 모든 선수는 공을 잃은 뒤 다시 뛰어야 한다.

우윙 역시 공격 전개에 많은 역할을 맡지만,\
공격이 끝난 뒤 수비 참여를 면제받지는 않는다.

#### 역할 하한선

우윙은 여러 기능을 동시에 수행하는 역할이므로,\
한 가지 능력만 압도적으로 높은 선수가 높은 평가를 받지 않도록 하한선을 둔다.

초안에서는 다음 기준을 사용한다.

```text
Playmaking < 12
ChanceCreation < 11
DefWork < 12
```

각 기준 미달분의 0.5배를 합산해 한 번 감점한다. 상세 계산은 공통 보정 규칙을 따른다.

특히 `Playmaking`은 이 역할의 정체성이므로,\
플레이메이킹 능력이 낮은 선수는 드리블이나 득점력이 높더라도\
우윙 역할에서는 높은 평가를 받지 못하게 한다.

이 역할의 핵심은 **빠른 윙어**가 아니라\
**오른쪽에서 공을 많이 만지고, 판단하고, 연결하고, 창조하는 공격수**다.

### 5. 더블 볼란치 — 레지스타(지원) / 수비형 미드필더(지원)

더블 볼란치는 두 선수가 같은 일을 나눠 하는 구조가 아니다.

한 명은 **레지스타로서 공격의 방향을 자유롭게 결정하고**,
다른 한 명은 **수비형 미드필더로서 레지스타와 주변 선수들의 움직임을 읽고
비어진 기능을 채우는 역할**을 맡는다.

현재 전술 구조에서는
우윙이 중앙으로 들어오거나 내려와 플레이메이킹을 하기 때문에,
레지스타를 왼쪽에 두고 수비형 미드필더를 오른쪽에 두는 안을 우선 검토한다.

즉,

```text
LDM = Regista (Support)
RDM = Defensive Midfielder (Support)
```

를 현재 우선안으로 둔다.

---

#### 좌볼란치 — 레지스타(지원)

레지스타는 단순한 후방 플레이메이커가 아니라
**자신의 판단에 따라 위치를 바꾸며 공격을 지휘하는 자유로운 미드필더**다.

현재 후보는 흐라벤베르흐와 Nyoni다.

특히 천재성, 패스, 시야, 침착성을 중요하게 본다.

```text
DM_REG_S =
0.30 * Creation
+ 0.25 * Composure
+ 0.20 * Freedom
+ 0.15 * BallSecurity
+ 0.10 * Defence
```

| 하위 지수            |  비중 | 의미                              |
| ---------------- | --: | ------------------------------- |
| **Creation**     | 30% | 후방과 중원에서 공격 방향을 결정하는 패스 능력      |
| **Composure**    | 25% | 압박 속에서도 플레이를 유지하는 침착성           |
| **Freedom**      | 20% | 상황에 따라 자유롭게 움직이고 창조적인 선택을 하는 능력 |
| **BallSecurity** | 15% | 공을 받아 지키고 다음 장면으로 연결하는 능력       |
| **Defence**      | 10% | 최소한의 수비 기여                      |

##### Creation — 창조성

```text
0.30 * 패스
+ 0.25 * 시야
+ 0.15 * 판단
+ 0.15 * 기술
+ 0.10 * 예측
+ 0.05 * 트랩
```

##### Composure — 침착성

```text
0.40 * 침착
+ 0.20 * 판단
+ 0.15 * 트랩
+ 0.15 * 기술
+ 0.10 * 집중
```

##### Freedom — 자유로운 플레이

```text
0.35 * 천재성
+ 0.20 * 판단
+ 0.15 * 오프더볼
+ 0.15 * 예측
+ 0.15 * 시야
```

레지스타에게는 천재성을 특히 중요하게 본다.

정해진 위치와 패턴만 반복하는 것이 아니라,
경기 상황을 보고 직접 더 좋은 해결책을 선택하는 능력이 필요하기 때문이다.

##### BallSecurity — 공 보존

```text
0.25 * 트랩
+ 0.20 * 기술
+ 0.15 * 침착
+ 0.15 * 드리블
+ 0.10 * 균형
+ 0.10 * 판단
+ 0.05 * 몸싸움
```

##### Defence — 수비 기여

```text
0.25 * 위치선정
+ 0.20 * 예측
+ 0.20 * 태클
+ 0.15 * 판단
+ 0.10 * 집중
+ 0.10 * 팀워크
```

---

#### 우볼란치 — 수비형 미드필더(지원)

수비형 미드필더는 레지스타의 반대 역할이다.

직접 공격을 지휘하는 것이 아니라
**레지스타와 주변 선수들의 움직임을 읽고 비어진 공간과 기능을 채운다.**

레지스타가 올라가면 아래에 남아 빌드업을 돕고,
레지스타가 박스로 들어가면 수비 진영을 지키며,
레지스타가 공을 받으러 내려오면 한 칸 전진해 중원의 숫자를 유지한다.

현재는 에릭 가르시아, 아치 그레이, 아유브 부아디를 사용한다.

이 역할에서는 천재성보다
**판단력, 수비력, 다재다능함, 신체 조건**을 중요하게 본다.

```text
DM_S =
0.30 * Decision
+ 0.30 * Defence
+ 0.15 * Support
+ 0.15 * Physical
+ 0.10 * BuildUp
```

| 하위 지수        |  비중 | 의미                             |
| ------------ | --: | ------------------------------ |
| **Decision** | 30% | 주변 선수의 움직임을 보고 필요한 역할을 선택하는 능력 |
| **Defence**  | 30% | 중앙 공간과 수비 라인 앞을 보호하는 능력        |
| **Support**  | 15% | 빌드업과 전진을 상황에 맞게 보조하는 능력        |
| **Physical** | 15% | 경합과 커버에 필요한 신체 조건              |
| **BuildUp**  | 10% | 후방에서 안전하게 공을 연결하는 능력           |

##### Decision — 상황 판단

```text
0.40 * 판단
+ 0.20 * 예측
+ 0.15 * 위치선정
+ 0.15 * 팀워크
+ 0.10 * 집중
```

이 역할의 가장 중요한 능력 중 하나다.

수비형 미드필더는 자신이 하고 싶은 플레이보다
**현재 팀 구조에 무엇이 필요한지를 읽는 능력**이 중요하다.

##### Defence — 수비력

```text
0.25 * 태클
+ 0.20 * 마크
+ 0.20 * 위치선정
+ 0.15 * 예측
+ 0.10 * 집중
+ 0.10 * 몸싸움
```

##### Support — 다재다능한 지원

```text
0.25 * 패스
+ 0.20 * 트랩
+ 0.20 * 오프더볼
+ 0.15 * 팀워크
+ 0.10 * 판단
+ 0.10 * 활동량
```

##### Physical — 신체 조건

```text
0.30 * 몸싸움
+ 0.20 * 지구력
+ 0.20 * 주력
+ 0.15 * 순간속도
+ 0.15 * 점프
```

기본적으로 **185cm 미만의 선수는 선호하지 않는다.**

센터백과 마찬가지로 신장은 절대 조건이라기보다
수비력과 경합 능력을 보완하는 하한선으로 사용한다.

이 역할은 화려한 창조성보다

**누군가 움직이면 그 빈자리를 채우고,
팀 구조가 무너지지 않도록 다음 위치를 선택하는 균형 관리자**에 가깝다.

##### BuildUp — 후방 연결

```text
0.30 * 패스
+ 0.20 * 트랩
+ 0.15 * 판단
+ 0.15 * 침착
+ 0.10 * 기술
+ 0.10 * 시야
```

### 6. 좌풀백 — 완성형 윙백(지원)

좌풀백은 우풀백보다 역할이 훨씬 유동적이다.

좌윙이 포처처럼 박스로 들어가면 바깥 폭을 제공하고,
공격 숫자가 충분하면 뒤에 남아 뒷공간을 커버하며,
상황에 따라 직접 전진하거나 중앙의 빌드업을 도울 수도 있어야 한다.

현재는 케르케즈와 Amass를 사용한다.

이 역할의 핵심은 특정 기술 하나보다 **다재다능함과 상황 대응력**이다.

```text
LB_CWB_S =
0.25 * Intelligence
+ 0.25 * Mobility
+ 0.20 * Work
+ 0.15 * Creation
+ 0.15 * Defence
```

| 하위 지수            |  비중 | 의미                     |
| ---------------- | --: | ---------------------- |
| **Intelligence** | 25% | 상황을 읽고 다른 역할을 선택하는 능력  |
| **Mobility**     | 25% | 전진과 복귀를 모두 수행하는 기동력    |
| **Work**         | 20% | 경기 내내 여러 역할을 반복하는 활동량  |
| **Creation**     | 15% | 크로스와 패스로 공격에 기여하는 능력   |
| **Defence**      | 15% | 좌윙이 비운 공간을 커버하는 기본 수비력 |

#### Intelligence — 전술적 판단

```text
0.35 * 판단
+ 0.25 * 천재성
+ 0.15 * 예측
+ 0.15 * 오프더볼
+ 0.10 * 팀워크
```

특히 **천재성, 판단력**을 중요하게 본다.

완성형 윙백은 정해진 한 가지 행동을 반복하는 선수가 아니라,
경기 상황에 따라 다른 해답을 선택해야 하기 때문이다.

#### Mobility — 기동력

```text
0.30 * 순간속도
+ 0.25 * 주력
+ 0.15 * 민첩
+ 0.15 * 지구력
+ 0.15 * 오프더볼
```

#### Work — 활동량

```text
0.40 * 활동량
+ 0.25 * 지구력
+ 0.15 * 팀워크
+ 0.10 * 승부욕
+ 0.10 * 판단
```

#### Creation — 공격 기여

```text
0.35 * 크로스
+ 0.20 * 패스
+ 0.15 * 기술
+ 0.15 * 시야
+ 0.15 * 판단
```

기본 공격 무기는 크로스지만,
역발 풀백의 경우 슈팅 능력이 좋다면 공통 규칙의 조건부 보너스로 인정한다.

#### Defence — 공간 커버

```text
0.25 * 위치선정
+ 0.20 * 태클
+ 0.15 * 마크
+ 0.15 * 예측
+ 0.10 * 판단
+ 0.10 * 집중
+ 0.05 * 팀워크
```

### 7. 좌센터백 — 중앙 수비수(수비)

좌센터백은 공격형 수비수보다
**수비 구조를 안정시키고 위험 상황에서 실수 없이 정리하는 역할**에 가깝다.

따라서 발밑보다 침착성과 수비 안정성을 더 중요하게 본다.

```text
LCB_CD_D =
0.30 * Composure
+ 0.25 * Defence
+ 0.20 * Recovery
+ 0.15 * Aerial
+ 0.10 * BuildUp
```

#### Composure — 안정성

```text
0.40 * 침착
+ 0.20 * 판단
+ 0.15 * 집중
+ 0.15 * 예측
+ 0.10 * 트랩
```

#### Defence — 수비력

```text
0.25 * 태클
+ 0.20 * 마크
+ 0.20 * 위치선정
+ 0.15 * 예측
+ 0.10 * 집중
+ 0.10 * 판단
```

#### Recovery — 속도

```text
0.35 * 주력
+ 0.30 * 순간속도
+ 0.15 * 예측
+ 0.10 * 판단
+ 0.10 * 민첩
```

우센터백과 마찬가지로
주력과 순간속도를 중요한 하한 능력으로 본다.

#### Aerial — 제공권

```text
0.35 * 점프
+ 0.30 * 헤더
+ 0.20 * 몸싸움
+ 0.15 * 예측
```

#### BuildUp — 안정적인 후방 연결

```text
0.30 * 패스
+ 0.20 * 트랩
+ 0.15 * 침착
+ 0.15 * 판단
+ 0.10 * 기술
+ 0.10 * 시야
```

### 8. 우센터백 — 공격형 수비수(수비)

우센터백은 수비뿐 아니라
**후방 빌드업에서 압박을 깨고 전진 패스를 공급하는 역할**을 맡는다.

현재 주전 조합에서는 자케 또는 레오니,
로테이션 조합에서는 Salmon 또는 Juma Abh 중
빌드업에 더 강한 선수를 이 역할에 배치하는 것을 기본으로 한다.

```text
RCB_BPD_D =
0.30 * BuildUp
+ 0.20 * Composure
+ 0.20 * Recovery
+ 0.20 * Defence
+ 0.10 * Aerial
```

#### BuildUp — 후방 전개

```text
0.30 * 패스
+ 0.20 * 시야
+ 0.20 * 기술
+ 0.15 * 트랩
+ 0.15 * 판단
```

단순 안전 패스보다
상대 1차 압박을 넘어가는 전진 패스와 볼 처리 능력을 높게 평가한다.

#### Composure — 압박 대응

```text
0.40 * 침착
+ 0.20 * 판단
+ 0.15 * 집중
+ 0.15 * 예측
+ 0.10 * 트랩
```

#### Recovery — 뒷공간 회복

```text
0.35 * 주력
+ 0.30 * 순간속도
+ 0.15 * 예측
+ 0.10 * 민첩
+ 0.10 * 판단
```

높은 라인을 유지하기 때문에
속도와 가속도는 두 센터백 모두 매우 중요하게 본다.

#### Defence — 수비력

```text
0.25 * 태클
+ 0.20 * 마크
+ 0.20 * 위치선정
+ 0.15 * 예측
+ 0.10 * 집중
+ 0.10 * 판단
```

#### Aerial — 제공권

```text
0.35 * 점프
+ 0.30 * 헤더
+ 0.20 * 몸싸움
+ 0.15 * 예측
```

#### 센터백 공통 조건

센터백은 가중평균만으로 평가하지 않는다.

특히 다음 두 조건을 중요하게 본다.

##### 속도

높은 수비 라인을 유지하기 때문에
`Recovery` 12 미만이면 부족분의 0.5배를 감점한다.
또한 주력 또는 순간속도 자체가 10 미만이면 느린 쪽의 부족분도 확인한다.
두 속도 감점 중 큰 값만 적용하며, 상세 계산은 공통 보정 규칙을 따른다.

##### 신장

기본적으로 **185cm 미만의 센터백은 선호하지 않는다.**

다만 185cm 미만이라도
점프력, 헤더, 몸싸움이 매우 뛰어난 경우 일부 상쇄할 수 있도록 한다.
감점과 상쇄는 공통 규칙의 신장 보정을 한 번 적용한다.

### 9. 우풀백 — 풀백(공격)

우풀백은 우윙이 중앙으로 들어오거나 공을 받으러 내려올 때,
오른쪽 터치라인을 점유하며 **폭을 넓히고 전방 숫자를 늘리는 역할**이다.

현재는 팔레스트라와 브래들리를 주로 사용한다.

이 역할에서는 균형 잡힌 평균형 풀백보다
**크로스나 드리블에 확실한 공격 무기 하나를 가진 선수**를 높게 평가한다.
역발 슈팅은 기본 역할 수행 능력을 확인한 뒤 별도 보너스로 반영한다.

왼발잡이더라도 반대발을 어느 정도 사용할 수 있고,
안쪽으로 들어왔을 때 슈팅이 좋다면 충분히 활용 가능하다.

최종 적합도 가안은 다음과 같다.

```text
RB_FB_A =
0.30 * AttackWeapon
+ 0.25 * Overlap
+ 0.20 * Decision
+ 0.15 * Work
+ 0.10 * Defence
```

| 하위 지수            |  비중 | 의미                              |
| ---------------- | --: | ------------------------------- |
| **AttackWeapon** | 30% | 크로스 또는 드리블 중 확실한 공격 강점 |
| **Overlap**      | 25% | 우윙이 비운 측면을 읽고 전진하는 능력           |
| **Decision**     | 20% | 높은 위치에서 올바른 공격 선택을 하는 능력        |
| **Work**         | 15% | 오버래핑과 복귀를 반복할 수 있는 활동량          |
| **Defence**      | 10% | 최소한의 1대1 수비와 위치 안정성             |

#### AttackWeapon — 공격 무기

우풀백의 공격 능력은 단순 평균보다
가장 강한 공격 방식 하나를 우선적으로 평가한다.

**크로스형**

```text
0.45 * 크로스
+ 0.20 * 기술
+ 0.15 * 시야
+ 0.10 * 패스
+ 0.10 * 판단
```

**돌파형**

```text
0.35 * 드리블
+ 0.20 * 순간속도
+ 0.15 * 민첩
+ 0.15 * 기술
+ 0.15 * 주력
```

```text
AttackWeapon = max(크로스형, 돌파형)
```

역발 슈팅은 아래 공통 규칙의 조건부 보너스로만 반영해 중복 계산하지 않는다.

즉 모든 공격 능력이 평균 이상일 필요는 없지만,
**상대가 반드시 신경 써야 하는 공격 무기 하나는 있어야 한다.**

#### Overlap — 폭 제공 / 오버래핑

```text
0.25 * 오프더볼
+ 0.20 * 순간속도
+ 0.15 * 주력
+ 0.15 * 판단
+ 0.15 * 예측
+ 0.10 * 지구력
```

우윙의 움직임을 보고 비어진 터치라인으로 들어가는 타이밍을 평가한다.

#### Decision — 판단력

```text
0.40 * 판단
+ 0.20 * 시야
+ 0.15 * 예측
+ 0.10 * 침착
+ 0.10 * 팀워크
+ 0.05 * 오프더볼
```

우풀백은 높은 위치에서 공을 받은 뒤
크로스, 돌파, 컷백, 재순환 중 하나를 빠르게 선택해야 한다.

따라서 판단력은 개별 공격 기술과 별개로 중요한 능력으로 본다.

#### Work — 활동량

```text
0.40 * 활동량
+ 0.30 * 지구력
+ 0.15 * 팀워크
+ 0.15 * 판단
```

공격 시 높은 위치까지 올라간 뒤
공을 잃으면 다시 수비 위치로 복귀해야 한다.

#### Defence — 기본 수비

```text
0.25 * 태클
+ 0.20 * 위치선정
+ 0.15 * 마크
+ 0.15 * 예측
+ 0.10 * 판단
+ 0.10 * 집중
+ 0.05 * 팀워크
```

### 10. 골키퍼 — 스위퍼 키퍼(공격)

골키퍼는 단순 선방형보다
**후방 빌드업에 직접 참여하는 공격적인 스위퍼 키퍼**를 선호한다.

현재는 Diogo Costa와 Kauã Santos를 사용한다.

특히 발밑, 판단력, 침착성을 중요하게 본다.

```text
GK_SK_A =
0.30 * Distribution
+ 0.25 * Decision
+ 0.20 * Composure
+ 0.25 * Goalkeeping
```

| 하위 지수            |  비중 | 의미                           |
| ---------------- | --: | ---------------------------- |
| **Distribution** | 30% | 압박을 받아도 후방에서 공격을 시작하는 능력     |
| **Decision**     | 25% | 전진, 패스, 걷어내기, 커버 여부를 판단하는 능력 |
| **Composure**    | 20% | 상대 압박 속에서도 침착하게 플레이하는 능력     |
| **Goalkeeping**  | 25% | 기본적인 선방과 골키핑 능력              |

#### Distribution — 발밑

```text
0.35 * 패스
+ 0.20 * 트랩
+ 0.15 * 기술
+ 0.15 * 시야
+ 0.15 * 판단
```

킥/골킥 컬럼의 의미가 확인되기 전까지는 위 다섯 능력만 사용한다.
현재 가안에는 킥 항목을 대체하거나 추정해 넣지 않는다.
추후 매핑이 확인되면 별도 공식 버전에서 비중 10~15% 도입을 검토한다.

#### Decision — 판단

```text
0.40 * 판단
+ 0.20 * 예측
+ 0.15 * 위치선정
+ 0.15 * 집중
+ 0.10 * 팀워크
```

#### Composure — 침착

압박 속에서 공을 받고 판단해 처리하는 능력을 복합지수로 본다.

```text
0.40 * 침착
+ 0.20 * 판단
+ 0.15 * 트랩
+ 0.10 * 패스
+ 0.10 * 집중
+ 0.05 * 기술
```

상대 공격수가 압박하더라도
불필요하게 급하게 걷어내지 않고 빌드업을 이어갈 수 있어야 한다.

#### Goalkeeping — 기본 골키핑

```text
0.30 * 반사신경
+ 0.20 * 1대1
+ 0.15 * 핸들링
+ 0.15 * 위치선정
+ 0.10 * 집중
+ 0.10 * 공중볼장악
```

공중볼장악은 export의 `장악`, 내부 키 `command_of_area`에 연결한다.

발밑이 아무리 좋아도 기본 골키핑이 지나치게 낮은 선수는
높은 평가를 받지 않도록 `Goalkeeping` 12를 하한으로 둔다.

### 공통 보정·데이터 규칙 — v0.1.1 완성 초안

아래 규칙으로 모든 역할의 최종 점수까지 계산한다. 가중치·하한·보정 계수는
사용자의 전술적 선호를 표현한 초안이며, FM 경기 엔진의 실제 효과를 추정한 수치는 아니다.
이름이 같은 하위 지수도 **해당 역할에 적힌 공식**을 사용한다.
예를 들어 좌우 풀백의 `Defence`, 좌우 센터백의 `BuildUp`은 서로 다르다.

#### 최종 점수와 계산 순서

각 역할에 제시한 `ST_CF_A`, `ST_AF_A`, `LW_IFA`, `AM_A`, `RW_IWS`,
`DM_REG_S`, `DM_S`, `LB_CWB_S`, `LCB_CD_D`, `RCB_BPD_D`, `RB_FB_A`, `GK_SK_A`는
감점 전 기본 점수 `BaseScore`다. 역할 하한 감점, 신장 감점, 속도 감점은 모두 **양수 감점량**으로 정의한다.

```text
FinalScore = clamp(BaseScore - RolePenalty - HeightPenalty - SpeedPenalty + ShotBonus, 1, 20)
clamp(x, 1, 20) = min(20, max(1, x))
```

1. 원본 능력치로 하위 지수와 기본 점수를 계산한다.
2. 역할 하한·신장·속도 감점량을 각각 계산한다. 적용 대상이 아니면 0이다.
3. 좌우 풀백에 한해 역발 슈팅 보너스의 자격 조건을 확인한다.
4. 보정을 각각 한 번만 적용한 후 최종 점수를 1~20으로 제한한다.

중간 계산은 반올림하지 않는다. 표시할 때만 소수 둘째 자리까지 반올림하고,
순위와 격차 비교에는 반올림 전 값을 사용한다. 좌윙 본문의 감점도 여기의 `RolePenalty`와
같은 규칙이므로 다시 더하지 않는다. 점수 비교는 같은 역할 안에서 한다.

#### 역할별 핵심 축 하한

```text
RolePenalty = 0.50 * sum(max(0, 기준값 - 해당_축_점수))
```

아래 표의 모든 하한 미달분을 합산한다. 표에 없는 축에는 별도 하한 감점을 적용하지 않는다.

| 역할 | 하한 기준 |
| --- | --- |
| 완성형 포워드(공격) | `Finishing` 12, `HoldUp` 12 |
| 전진형 포워드(공격) | `Finishing` 12, `Run` 12 |
| 좌윙 | `DefWork` 12 |
| 공미 | `PocketCreation` 12 |
| 우윙 | `Playmaking` 12, `ChanceCreation` 11, `DefWork` 12 |
| 레지스타 | `Creation` 12 |
| 수비형 미드필더 | `Decision` 12, `Defence` 12 |
| 좌풀백 | `Intelligence` 12, `Work` 12, `Defence` 11 |
| 좌센터백 | `Composure` 12, `Defence` 12 |
| 우센터백 | `BuildUp` 12, `Defence` 12 |
| 우풀백 | `Decision` 12, `Work` 12, `Defence` 11 |
| 골키퍼 | `Goalkeeping` 12 |

공격 강점만으로 기본 역할의 부족함을 모두 가리지 못하게 하는 장치다.
예를 들어 우윙의 세 축이 각각 11, 10, 10이면 감점은 `0.5 × (1 + 1 + 2) = 2.0`이다.

#### 신장 감점과 제공권 상쇄

**완성형 포워드, 수비형 미드필더, 좌우 센터백**에만 적용한다. 기준 신장은 185cm다.
`Height`는 cm 단위이며, `HeightPenalty`는 최종 점수에서 빼는 양수다.

```text
HeightShortfall = max(0, 185 - Height)
ReliefRate = min(0.50, max(0, (HeightAerial - 14) * 0.10))
HeightPenalty = 0.15 * HeightShortfall * (1 - ReliefRate)
```

- 완성형 포워드의 `HeightAerial`은 해당 역할의 `Aerial` 점수다.
- 좌우 센터백의 `HeightAerial`은 해당 역할의 `Aerial` 점수다.
- 수비형 미드필더는 다음 보정용 제공권 점수를 계산한다. 기본 점수에 추가하는 축은 아니다.

```text
DM_HeightAerial =
0.35 * 점프
+ 0.30 * 헤더
+ 0.20 * 몸싸움
+ 0.15 * 예측
```

수비형 미드필더는 `HeightAerial = DM_HeightAerial`을 사용한다.
제공권 14 이하는 상쇄하지 않고, 16이면 20%, 19 이상이면 최대 50% 상쇄한다.
예를 들어 180cm에 제공권 16이면 신장 감점은 `0.15 × 5 × 0.8 = 0.60`이다.
키가 185cm 이상이라고 가산점을 주지는 않는다.

#### 센터백 속도 감점

좌우 센터백에만 적용한다. 종합 회복 능력뿐 아니라 주력·순간속도 중 하나가
지나치게 낮은 경우도 확인한다. 동일한 약점을 중복 감점하지 않도록 두 값 중 큰 것만 사용한다.

```text
RecoveryPenalty = 0.50 * max(0, 12 - Recovery)
RawSpeedPenalty = 0.50 * max(0, 10 - min(주력, 순간속도))
SpeedPenalty = max(RecoveryPenalty, RawSpeedPenalty)
```

`Recovery`는 각 센터백의 세부 공식으로 계산한다. 이 축은 역할 하한 표에서 제외했으므로
`RolePenalty`에 또 합산하지 않는다. 다른 역할의 속도는 기존 가중평균 안에서만 평가한다.

#### 좌우 풀백의 역발 슈팅 보너스

```text
ShotScore =
0.40 * 골결
+ 0.30 * 중거리
+ 0.20 * 침착
+ 0.10 * 기술
```

아래 조건을 **모두** 만족하면 보너스를 준다.

- 우풀백은 왼발 우세, 좌풀백은 오른발 우세다. 양발잡이는 양쪽 자리 모두 자격이 있다.
- 약발 능력이 1~20 척도에서 **10 이상**으로 확인돼 있다. 양발 표기만으로 수치를 추정하지 않는다.
- 해당 풀백의 역할 하한 표에 있는 모든 축이 기준 이상이다.

```text
ShotBonus = 0.05 * max(0, ShotScore - 10)  # 모든 조건을 충족할 때
ShotBonus = 0                            # 그 외
```

보너스는 최대 0.5점이며 슈팅이 낮아도 감점으로 바꾸지 않는다.
우풀백의 `AttackWeapon`은 크로스형·돌파형의 최댓값만 사용하고,
좌풀백의 `Creation`도 원래 공식을 유지한다. 슈팅은 이 보너스에서만 반영한다.

현재 정규화 필드에는 `preferred_foot`만 있고 약발 숙련도 전용 필드는 없다.
초안의 추가 입력 `weak_foot_score`(1~20, 선택값)는 확인 가능한 수치가 있을 때만 수동 입력하는 것으로 정의한다.
실제 저장·입력 기능은 아직 구현하지 않았다. 주발 또는 약발 정보가 없거나 모호하면
보너스는 0으로 계산하고 **역발 보너스 미평가**라고 표시한다. 기본 점수는 계산할 수 있다.

#### 능력치 연결과 결측값

문서의 표현 차이는 아래 내부 키로 통일한다. 나머지는 `src/config.py`의 능력치 매핑을 따른다.

필수 능력치는 1~20 범위의 실제 관측값을 사용한다. 결측값을 0이나 평균값으로 채우지 않는다.
기본 점수에 필요한 능력치가 하나라도 없거나 범위 밖이면 관련 축과 기본·최종 점수는 **계산 불가**로 표시한다.
우풀백 `AttackWeapon`도 두 공격 유형을 모두 계산할 데이터가 있어야 한다.
신장 보정 대상인데 키가 없거나 유효한 양수가 아니면 기본 점수만 표시하고 최종 점수는 계산하지 않는다.
신장이 185cm 미만인데 보정용 제공권을 계산할 수 없는 경우도 기본 점수만 표시한다.
185cm 이상이면 제공권 상쇄 계산 없이 신장 감점 0으로 처리한다.
최종 점수가 없는 선수는 역할별 점수 순위와 점수 기반 추천에서 제외하되, 누락 원인은 보여준다.
역발 보너스용 정보(주발·약발·슈팅 능력치)만 없거나 범위 밖인 경우는 보너스 0과 **역발 보너스 미평가**로 처리한다.

GK 킥/골킥 항목은 현재 공식에서 제외했으므로 누락으로 취급하지 않는다.
`gk_communication`은 코드에서도 원래 항목명이 불확실하다고 명시되어 있어 이번 공식에 넣지 않는다.
추후 데이터 매핑이나 가중치를 바꾸면 새로운 공식 버전으로 구분한다.

이 절은 **문서상의 완성된 계산 가안**이다. 실행 중인 `quality`와 `FORMULA_VERSION`은 여전히 v0.1이며,
실제 계산 코드·입력 UI·재계산·클라우드 동기화는 이번 문서 변경에 포함하지 않는다.

## 6. FM24 HTML의 까다로운 점과 대응

실제 export(384컬럼, 42명)를 뜯어보고 대응한 것들.

### 중복 컬럼명

`최적 역할` ×5, `잠재력` ×3, `구단` ×2, `시작` ×2, `능력` ×2, `PK` ×2 …

- 모든 컬럼을 `__2`, `__3` 접미로 보존한다. 하나도 버리지 않는다.
- 정규화 필드는 **위치가 아니라 값의 모양**으로 고른다.
  `구단` 두 개 중 `{1군, U23, U18}` 에 해당하는 쪽이 `squad_level`,
  나머지가 `club`. `시작` 두 개 중 날짜 형식인 쪽이 `contract_start`,
  정수인 쪽이 `starts`.
- 판별기는 `config.DISAMBIGUATORS` 에 함수로 등록돼 있다.
  판별기가 어느 쪽도 못 고르면 **NULL로 둔다**. 틀린 값을 넣지 않는다.

### 한국어 표기

| export 값 | 파싱 결과 |
|---|---|
| `원1,800억` | `180000000000` |
| `원290억 - 원440억` | low `29000000000` / high `44000000000` / value 중간값 |
| `원436.09억` | `43609000000` |
| `원3,350만` | `33500000` |
| `연봉 원377억` | amount `37700000000`, period `annual` |
| `27 (4)` | starts `27`, subs `4` |
| `2001년/12월/12일 (25세)` | `2001-12-12`, 나이 25 |
| `86%` | `86.0` |
| `184 cm` / `71 kg` / `370.2km` | `184.0` / `71.0` / `370.2` |
| `-`, `--`, 빈칸 | `NULL` |

`없음`, `미설정` 은 **결측이 아니라 실제 값**이므로 그대로 텍스트로 둔다.

### 빈 섹션 헤더

`능력`, `잠재력`, `성과`, `체력` 컬럼은 FM 화면의 섹션 구분선이 그대로
export된 것이라 전 행이 비어 있다. 억지로 해석하지 않고 raw로만 둔다.

### FM 인라인 마크업

`Richard Olise |c:disabled|형제|/c|` → `Richard Olise (형제)`

### 컬럼이 바뀌어도 안 깨지게

- 못 찾은 필드는 조용히 NULL이 된다. 예외를 던지지 않는다.
- 각 필드는 후보 헤더를 여러 개 가질 수 있다 (`("F/PT", "유형")`).
- 능력치 컬럼을 못 찾으면 요약에 경고로 나온다.

### 능력치 컬럼 찾기 도우미

`config.ATTRIBUTE_GROUPS` 에는 **확신이 있는 능력치만** 넣었다.
빠진 것을 찾으려면:

```powershell
python scripts/update.py --file data/players.html --date 2027-03-01 --dry-run --suggest-attributes
```

값이 대부분 1~20 정수인 미등록 컬럼을 보여준다. 출전 수처럼 우연히 범위에
들어오는 것도 섞이니 사람이 보고 판단해서 config에 추가한다.
추가 후 과거 데이터까지 채우려면 `data/raw/` 의 HTML을 다시 import한다.

정규화 안 된 컬럼 전체 목록:

```powershell
python scripts/update.py --file data/players.html --date 2027-03-01 --dry-run --show-unmapped
```

## 8. 앞으로 답하고 싶은 질문들

이 구조는 다음 분석을 위한 기반이다. 지금은 답할 수 없고,
**시즌을 여러 번 누적해야** 답이 나온다.

- 어린 선수를 1군에서 많이 굴리면 실제로 더 빨리 성장하는가?
- 17 / 18 / 19세에 같은 출전시간을 받았을 때 성장량 차이는?
- 특출난 유망주(`talent_score` 높음)와 균형형(`balance_score` 높음) 중
  어느 쪽이 더 잘 성장하는가?
- 육성조 → 부주전 → 주전 경로는 실제로 어떻게 흘러가는가?
- 영입 당시 능력치 프로필이 2~3시즌 뒤 성장량을 얼마나 설명하는가?

필요한 데이터는 이미 다 저장되고 있다. 예를 들어 "출전시간 대비 성장" 은:

```sql
SELECT p.name,
       s.age,
       s.minutes,
       gm.value_num AS growth_total
FROM snapshots s
JOIN players p          ON p.player_id = s.player_id
JOIN derived_metrics gm ON gm.player_id = s.player_id
                       AND gm.game_date = s.game_date
                       AND gm.metric = 'attribute_growth_total'
WHERE s.age <= 21
ORDER BY gm.value_num DESC;
```

## 9. 알려진 한계

**목적에 직접 영향을 주는 것부터:**

- **스냅샷이 2개 이상이어야 아무것도 답할 수 있다.** 지금은 1개뿐이라
  성장 열이 전부 비어 있다. 이건 코드가 아니라 시간 문제다.
- **영입/유스 판정이 추론이다.** 이적료와 이전 구단으로 가른다.
  영입 직후 임대를 보낸 선수는 유스로 잘못 볼 수 있다(이적료가 있으면
  잡힌다). 사이트에서 직접 고칠 수 있고, 고친 값은 유지된다.
- **"방출" 은 사라졌다는 뜻일 뿐이다.** 방출·이적·계약만료를 FM export로는
  구분할 수 없다. export를 일부만 뽑아도 똑같이 사라진 것으로 보이므로,
  다음 시점에 다시 나타나면 그때부터 정상으로 돌아온다.
- **임대로 온 선수는 따로 구분하지 않는다.** FM에서 구단이 우리 팀으로
  찍히기 때문에 기존 선수와 같이 보인다. 영입/유스 판정에서는 `최근 구단` 이
  모구단과 달라 **영입으로 잡힌다.**
- **포지션 그룹이 굵다.** `AM(R)` 과 `AM(L)` 을 둘 다 `W`(윙어)로 묶어서,
  실제 export에서는 윙어 경쟁자가 17명으로 잡힌다. 좌우를 나누려면
  `config.POSITION_GROUPS` 를 고치면 된다.
- **Quality 목록 안에 가중치가 없다.** 포지션별로 볼 능력치는 구분하지만,
  그 안에서는 전부 동등하게 평균한다.

**그 밖에:**

- **Ceiling에 실제 근거가 없다.** export의 `잠재력` 컬럼이 비어 있다.
  FM 화면에서 PA를 보이게 설정할 수 있다면 그 컬럼을 export에 넣고
  `config.FIELD_SPECS` 에 추가하는 것이 가장 큰 개선이다.
- **Usage가 출장시간만 본다.** 리그전과 컵 하위 라운드를 구분하지 않는다.
- **능력치 매핑이 부분적이다.** 43개를 인식하지만 확신이 없는 컬럼은 뺐다
  (`막음`, `골킥`, 중복된 `스로인`). `조율` 은 값 분포로 GK 능력치인 것은
  확실하나 FM 원래 항목명은 모른다. 빠진 것들도 raw에는 남아 있다.
- **스냅샷 간격이 불규칙하면 성장 비교가 왜곡된다.** 시즌당 2~4회 등
  간격을 일정하게 뽑는 편이 낫다.
